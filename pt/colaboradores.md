# Colaboradores

**Português** · [English](../en/contributors.md)

Este projeto reconhece **toda forma de contribuição**, não só a de quem sabe mexer no GitHub. Traduzir, achar uma fonte melhor, apontar um erro de número, revisar um texto, sugerir um caminho, organizar dados, tornar o texto mais acessível: tudo isso é trabalho, e todo trabalho fica registrado com nome.

Contagem de commits não mede contribuição. Quem escreve um parágrafo decisivo aparece menor que quem corrige vírgula em quarenta arquivos, e isso é injusto com os dois. Por isso o crédito aqui é declarado, não calculado.

## As três camadas de crédito

O projeto credita em três lugares diferentes, e cada um responde a uma pergunta diferente.

**1. No rodapé de cada documento — quem respondeu por este texto.**
Todo documento termina com o registro editorial, que identifica o **modelo** de linguagem efetivamente usado e o **revisor** humano que respondeu pelo conteúdo. A regra está em [créditos editoriais](creditos-editoriais.md) e vale para toda publicação, sem exceção.

**2. Na tabela abaixo — quem participou do projeto e de que forma.**
É o retrato geral: cada pessoa aparece uma vez, com os tipos de contribuição que já fez. É aqui que alguém aponta, anos depois, onde entrou no trabalho.

**3. Nas notas de cada edição — quem fez o quê naquele período.**
Quando uma [edição](edicoes.md) é publicada, suas notas listam quem contribuiu desde a edição anterior e com o quê. Essa é a camada que dá a dimensão temporal: não só "participou", mas "participou disto, nesta época".

## Tipos de contribuição

| | Tipo | O que é |
|---|---|---|
| 🖋 | `content` | Escrever ou reescrever texto do acervo |
| 🔬 | `research` | Levantar evidência, investigar um caso, apurar um dado |
| 🌍 | `translation` | Traduzir entre os idiomas do projeto |
| 👀 | `review` | Revisar texto, conferir fontes, checar números |
| 🔣 | `data` | Coletar, organizar ou documentar dados brutos |
| 🤔 | `ideas` | Propor direção, método ou recorte |
| 📖 | `doc` | Escrever documentação do projeto em si |
| 🐛 | `bug` | Apontar erro, incoerência ou link quebrado |
| ♿️ | `a11y` | Tornar o texto ou o site mais acessível |
| 🎨 | `design` | Trabalho visual |
| 💬 | `question` | Responder dúvidas de quem chega |
| 📆 | `projectManagement` | Organizar o trabalho, cuidar de issues e edições |

## Como pedir seu crédito

Você não precisa esperar que alguém se lembre de você. Em qualquer issue ou pull request do projeto, escreva um comentário no formato:

```
@all-contributors please add @seu-usuario for research, translation
```

O registro é acrescentado por pull request, e a tabela abaixo se atualiza. Se preferir, peça em português numa issue comum, dizendo o que fez e onde — alguém registra por você.

**Crédito não se recusa por modéstia e não se infla por insistência.** Registre o que você fez, com o tipo certo. Se discordar de como foi creditado, abra uma issue: corrige-se sem drama.

## Sobre a assistência de inteligência artificial

Os modelos de linguagem que participam do projeto **não entram nesta tabela**. Eles são identificados no rodapé de cada documento que ajudaram a redigir, junto do revisor humano que respondeu por aquele texto. A distinção é deliberada: esta tabela é de participantes do projeto; o registro editorial é de responsabilidade sobre um texto. Confundir as duas coisas apagaria a responsabilidade humana ou inventaria uma participação que o modelo não tem.

A [origem e os créditos](origem.md) do projeto explicam como intenção humana e assistência de IA se distinguem desde o começo.
